# Заметки: гибридный бэкенд (GPU на prefill, CPU на decode)

Идея: переключать бэкенд **по фазам** внутри одного запроса — гнать препроцессинг
(promt/prefill) на встроенном GPU, а генерацию токенов (decode) на CPU.

В `llama.cpp` так **нельзя**: там один статический флаг `-ngl` (число слоёв на GPU),
который действует на обе фазы сразу. Пары флагов вида
`--n-gpu-layers-prompt` / `--n-gpu-layers-gen` в исходниках и доках нет.
Есть только *частичный* offload (`-ngl 15` из 28 → половина слоёв GPU, половина CPU),
но сплит статичен и не меняется между фазами. Значит, если хотим такой гибрид —
пишем сами. Это и есть запланированная фича для этого движка.

## Замеренные цифры (тот же qwen2.5-1.5b Q4_K_M, i5-1135G7 + Iris Xe)

Проведено `scripts/benchmark_llm_gpu.py` в проекте `~/projects/va`:

| Фаза   | Ограничение | CPU (tok/s) | iGPU (tok/s) | Кто быстрее |
|--------|-------------|-------------|--------------|-------------|
| Prefill | compute (FLOPs) | 148.5 | 275.4 | **iGPU ×1.85** |
| Decode  | память ( bandwidth) | 23.0  | 16.1  | **CPU ×1.43**  |

Prefill — это большие батч-матричные умножения, на GPU Iris Xe много FP-ядер,
поэтому ~1.85× выигрыш. Decode — по одному токену за раз, каждый токен читает
**все** веса модели; у встроенного GPU та же физическая RAM (~68 ГБ/с), что и у
CPU, плюс накладные расходы диспетчеризации kernel'ов → CPU быстрее.

**Вывод:** если бы можно было переключать бэкенд по фазам, идеальный запрос ехал бы
на ~1.85× быстрее prefill и на ~1.43× быстрее decode, чем любой одноразовый выбор.

## Почему на встроенном GPU это сильно проще, чем на дискретном

Ключ — **unified memory**. Iris Xe физически читает ту же RAM, что CPU
(`uma: 1` в выводе `--list-devices`). Это отменяет главную боль гибрида:

- **Дискретная GPU:** веса живут в VRAM. Переключение фаз = копирование весов
  через PCIe (десятки ГБ) туда-и-обратно. Накладные расходы съедают весь выигрыш.
  Поэтому на десктопе гибрид почти бессмыслен.
- **Встроенная GPU:** веса — в общей RAM. CPU и GPU смотрят на одни и те же
  байты. Переключение фаз = смена *указателя на бэкенд*, а не копия данных.

Это главный аргумент, почему стоит реализовывать гибрид именно здесь.

## Что реально нужно переключать (два ресурса)

1. **Веса (weights).** Легко: из-за unified memory лежат в одном месте, оба
   бэкенда могут на них смотреть. Никакого копирования.
2. **KV-кэш.** Сложнее — вот настоящая загвоздка. Decode читает KV-кэш на
   каждом токене, поэтому он должен жить у того бэкенда, который делает decode
   (CPU). А prefill *пишет* KV-кэш. Значит при переключении GPU→CPU в конце
   prefill надо, чтобы GPU-записанный KV корректно читался CPU.

   Варианты:
   - **A (простой, медленный):** весь KV-кэш всегда в CPU-RAM. GPU при prefill
     пишет в общую RAM. Из-за unified memory это работает без копирования.
     Decode на CPU читает свой кэш локально. Prefill на GPU чуть медленнее из-за
     записи через общий контроллер памяти, но это один раз на токен промпта.
   - **B (быстрый, сложный):** держать два KV-кэша и синхронизировать при
     переключении. Для встроенного GPU бессмысленно — они и так в одной памяти.

   **Начинать с A.**

## Эскиз реализации

Граница переключения — это ровно граница prefill/decode, которую движок уже знает
(когда закончилась обработка промпта и началась генерация).

```
запрос:
  prefill  → dispatch(GPU, все токены промпта батчем)   // compute-bound
  переключение: только смена активного бэкенда           // без копирования весов
  for token in генерация:
      decode → dispatch(CPU, 1 токен)                    // memory-bound
```

Чек-лист:
- [ ] Два бэкенда за интерфейсом: `Cpu` (AVX-512 + VNNI, уже есть) и `Gpu`
      (Vulkan compute через `wgpu`/`ash`, отдельная задача).
- [ ] Трейт `Backend` с методом вида `matmul` / `forward_layer`, чтобы dispatch
      был полиморфным, а не `if cpu { } else { }` в каждом месте.
- [ ] `enum Phase { Prefill, Decode }` → выбор бэкенда в одном месте (scheduler).
- [ ] KV-кэш в общей CPU-RAM (вариант A), GPU пишет в него напрямую.
- [ ] Веса не дублировать: хранить один раз, оба бэкенда берут срезы из общего
      буфера (unified memory даёт это бесплатно).

## Осторожно: это ноу-хау привязано к iGPU

Стратегия «decode на CPU» верна **только** для встроенной GPU с общей памятью.
На дискретной GPU (отдельная VRAM с огромной пропускной способностью, например
GDDR6 ~300+ ГБ/с) decode на GPU выигрывает *у* CPU, потому что там памяти гораздо
больше, чем у CPU-контроллера. То есть «CPU быстрее для decode» — это
специфика unified memory, а не общее правило. Если в будущем появится дискретная
карта, эта логика переключается в обратную сторону (или становится бессмысленной).

## Порядок работ (если браться)

1. Сначала Vulkan/wgpu-бэкенд, который просто работает (пусть медленный).
2. Замерить: prefill и decode на GPU по отдельности (тот же `benchmark_llm_gpu.py`).
3. Добавить `Phase`-dispatch с KV-кэшем в общей RAM (вариант A).
4. Замерить гибрид против чистого CPU и чистого GPU — подтвердить ожидаемые
   ~1.85× prefill и ~1.43× decode.
5. Оптимизировать (если разница заметна): раздельные KV, батчинг, repack весов.
